# 固定アーキテクチャを前提にしたアプリ作成

## 今回の実装範囲

最初の機能は、既存の操作デモに「目的と利用者 → 画面の内容 → 作成内容の確認」を
追加する。確認した内容を固定テンプレートの画面見本へ渡し、作成時の目的・利用者・
確認項目を各アプリの編集画面に残す。これはAI-DLCのIntent/Requirements/Designの
入口を具体化するもので、実LLM、コード生成、ビルドexecutorや実起動の追加ではない。
通常版の管理API、Sandbox/Operation、RuntimeProviderの契約は変更しない。

## 二つの構成を混同しない

ProtoHub基盤はReact/Vite → FastAPI → PostgreSQL queue → Worker →
RuntimeProvider → Kubernetesが既定である。この管理基盤の構成が、そのまますべての
生成アプリの構成になるわけではない。アプリは基盤側で管理する、版付きの構成profileを
選択して作成する。利用者にDB製品や配布基盤を毎回選ばせない。

現在利用できるprofileは `trusted-preview-v1`。操作デモ専用の表示データであり、
生成コードや任意の実行命令を受け付けない。実アプリ向けprofileは別フェーズで、
許可した技術・依存・データ契約・検証方法・実行境界を確定してから追加する。

| 区分 | 今回のprofile |
| --- | --- |
| 固定 | 信頼済み画面テンプレート、サンプルデータ、既存の画面部品、外部送信なし |
| 変更可能 | アプリ名、説明文、配色、経営管理の推移グラフ・部門表・キャッシュフローの表示 |
| 要件として記録 | 目的、使う人、画面見本で確かめたいこと |
| 対象外 | 実データ保存、外部接続、認証・権限実装、コード生成、実アプリの起動・公開 |

要件の自由記述を表示設定への命令として解釈しない。目的に「外部API」「青い配色」と
書かれても接続したり配色を変えたりしない。画面に反映するものは、明示的に選んだ
表示設定だけとする。対象外の要望を実装済みと見せない。

## 質問と成果物

1. 目的と使う人を聞く。アプリ名と最初に試す画面を選び、未入力ならその項目へ戻す。
2. 選択した画面で使える機能だけ提示する。経営管理以外ではグラフ等を聞かない。
   利用者が何を確かめたいかを記録する。技術や秘密情報の入力は求めない。
3. 要件、表示項目、固定の前提と対象外を確認する。前の内容を修正でき、修正後の確認は
   最新の選択から組み立て直す。確認前に登録・模擬起動の処理を呼ばない。
4. 確認した表示設定をそのまま既存デモへ渡す。引用符などを命令文へ再変換しない。
   作成時の要件は編集画面で参照でき、後からの画面修正とは区別して残す。

成果物 `PreviewPlan` は `profile`、`brief`、`config` だけを持つ。
要件と表示計画を、テスト結果・承認トークン・実行状態として使わない。
現在はページ内メモリに保持し、再読み込みで消える。外部保存や費用は発生しない。
「作成内容の確認」は画面見本作成の確認であり、対象外機能の実行許可ではない。

## 受入条件

- BRIEF-01: 固定前提を再質問せず、目的・利用者・確認したいことを必須として記録する。
- BRIEF-02: 画面に応じた選択肢だけを表示し、画面変更時に無効な機能を持ち越さない。
- BRIEF-03: 確認前の作成、空欄の通過、作成処理中の二重送信を拒否する。
- BRIEF-04: 修正後の計画と画面が一致し、作成時の要件が後の修正・undoでも残る。
- BRIEF-05: API/LLMへの通信なしでブラウザ上の作成と修正を完了できる。
- BRIEF-06: 確認項目をPASS扱いせず、対象外と再読み込み時のリセットを明示する。

単体・画面テストは `app-brief.test.ts` と `DemoCreation.test.tsx`。
実ブラウザは `bash scripts/checks/pages-demo.sh` で通常buildへの混入防止、
静的デモ、確認からプレビューへの引継ぎ、修正、スマートフォン表示、通信境界を検証する。
これは実PostgreSQL/kindや実LLMの検証ではない。

## 実アプリ生成へ進むときの残作業

既存の [AI_DLC.md](AI_DLC.md) の永続workflowと実行境界に沿って、
アプリ向けprofile、版付き要件、生成物、検証証跡、モデル接続、費用上限、build隔離を
接続する。対象外の要望は未対応または判断待ちとして記録し、黙って標準構成を変えない。
固定の選択は再利用し、データの扱いや公開範囲など結果が変わる判断だけを聞く。
