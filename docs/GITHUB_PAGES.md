# GitHub Pages 操作デモ

既存のReact UIを使い、固定テンプレートの登録・起動・停止・削除・TTLと、モックAIへの指示による作成・修正をブラウザ内で再現する。
API・DB・Kubernetes・LLMへの通信は行わず、APIキーや有料サービスは不要。
画面に「操作デモ」を常時表示する。起動時に開けるサンプル画面は静的な見本であり、
実アプリを起動した証跡ではない。共有設定と受け取る側の画面はモックで再現する。実メールでのログイン、招待メールの送信、
本物のメンバー認証やブラウザ間の共有は提供しない。

作成画面の入力・状態・会話はメモリだけに保持し、再読み込みで初期状態へ戻る。
別タブの画面見本は、検証済みの表示設定をURLのfragment（#以降）へ渡す。
fragmentはサーバーに送られないが、タイトル・説明を含む見本URLがブラウザ履歴に残ることがある。
ほかの閲覧者・タブとは同期しない。実際の個人情報や業務データは入力しない。
通常ビルドと既存localhost用API・認証・実行基盤の動作は維持する。

## モックAIとテンプレート

「AIでアプリを作る」から以下を選べる。

- Hello Web: タイトル、説明文を持つWebページ。
- 経営管理ダッシュボード: 架空の売上・費用・営業利益・利益率と予算比較。

作成は「目的と利用者 → 画面の内容 → 作成内容の確認」の順に進める。
目的・使う人・確かめたいことを記録し、対応する表示内容を選び、
「この内容で画面見本を作成」で固定テンプレートを登録し模擬起動する。
作成時の要件と確認内容は編集画面で見返せる。固定の技術構成は再質問せず、
自由記述を表示命令として解釈しない。詳細は [APP_CREATION.md](APP_CREATION.md)。
追加の指示は定型ルールで解釈する。例:

- 「利益推移グラフを追加」「部門別の表を追加」「キャッシュフローを追加」
- 「グラフを削除」「部門別の表を非表示」
- 「青い配色に変更」「緑の配色に変更」「紫の配色に変更」
- 「タイトルを『月次経営レポート』に変更」「説明を『今月の経営状況』に変更」

会話、画面への反映、10段階までの取り消しを試せる。アプリを切り替えても変更は保持する。
対応しない指示は変更を行わなかった旨を返す。自由なコード生成・実行やLLMへの接続は行わない。
表示はすべて架空データで、外部データを取得しない。
追加テンプレートは静的デモ専用。backend/OpenAPIのhello-web限定を変更しない。
通常クライアントはデモ専用テンプレートの登録を送信前に拒否する。

## 共有体験のモック

アプリ詳細の「共有設定」で固定の「メンバーA」「メンバーB」を選び保存する。
「共有先の画面」で受け取るメンバーを切り替え、共有されたアプリの閲覧画面を確認できる。
共有された実行中アプリは、AIで変更した最新の画面見本を表示する。
受け取る側の見本にはAI編集・起動・停止・削除・共有編集の操作を置かない。
未共有のメンバーや共有解除後には画面を表示せず、停止・準備中・削除状態も区別する。
設定はアプリ別にページのメモリへ保持し、再読み込みで解除する。

これは所有者が同じページ内で共有体験を見せるデモであり、
本物のアクセス制御、招待、他のブラウザとの同期、期限付き/失効可能な公開URLを提供しない。
既存の別タブの画面見本URLは共有モックと独立した公開スナップショットのため、
この共有解除で失効するものではない。
localhost版の本来の共有API・所有者判定・認証契約は変更しない。

## ローカル確認

WSL/LinuxのNode 22.12以降（リポジトリの検証用はNode 24）を使用する。

```bash
cd apps/web
npm ci
npm run build:demo
npm run preview -- --port 4173
```

表示されたlocalhost URLから「操作デモを始める」を押す。
初期サンプルを選択し、起動→模擬起動中→サンプル画面を見る→停止→削除確認を試す。
新規登録・自動停止もブラウザ内で再現する。
ページを再読み込みすると初期サンプルだけに戻る。
通常のlocalhost版は従来どおり `npm run build` で作る。

検証には既存E2EのPlaywrightも使う。先に `npm ci --prefix tests/e2e` と
`tests/e2e/node_modules/.bin/playwright install chromium` を実行し、
`bash scripts/checks/pages-demo.sh` で確認する。OS依存が不足する場合はBLOCKEDとして扱い、
ユーザーのOS設定を自動変更しない。相対アセットURLを使用するため、
プロジェクトPagesの `/ai-prototype-hub/` 配下でも動作する。

## 公開

今回の公開先は静的成果物だけを持つ `gh-pages` ブランチ。PagesのSourceは
**Deploy from a branch / gh-pages / root**。再公開時は `npm run build:demo` と
ブラウザ検証を実行し、生成した `apps/web/dist/` の中身だけをこのブランチへ反映する。
通常のソースブランチやmainへ成果物を混ぜず、更新前に公開先の差分を確認する。

### 将来のActions公開へ切り替える場合

`.github/workflows/pages.yml` は手動実行専用。既存のCIとは独立する。
GitHubリポジトリの Settings → Pages → Build and deployment → Source を
**GitHub Actions** に設定する。Actions の **Publish browser demo** をmainで実行する。
検証後に `apps/web/dist/` だけをPages artifactへアップロードする。
リポジトリ全体、ローカル設定、提案書、worklogsはアップロードしない。
main以外からの公開はworkflowで拒否する。

既定URL: https://rararapi.github.io/ai-prototype-hub/

GitHub Pagesは公開サイトとして扱う。認証やメンバー限定アクセスを提供しない。
本物のバックエンドやLLMを公開するには別の設計と承認が必要。

参考: [GitHub公式のPages workflow手順](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。
